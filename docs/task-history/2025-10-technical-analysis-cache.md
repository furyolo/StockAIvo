# 技术分析缓存方案实施任务

## 背景
技术分析 Agent 目前以“市场状态日”为核心，每个交易日只产出一份综合分析结果，缺乏落地缓存，导致高频重复调用 Redis 与 Agent。分钟线缓存已经实现了基于交易时间的 TTL 动态调整能力，可作为复用基础。

## 目标
1. 复用现有市场状态感知逻辑，为技术分析结果提供稳定的 Redis 缓存。
2. 交易时间内保证 3 分钟短缓存，交易时间外缓存需在下一次开盘前自动失效。
3. 调用 Agent 前能够识别缓存命中并直接返回结果，同时保留必要的监控指标。

## 关键约束
- 缓存键命名固定为 `technical_analysis:{ticker}:{market_aware_date}`，其中 `market_aware_date` 为交易所时区下的日期字符串（如 `20250215`）。
- 缓存内容需包含原始分析文本、核心指标、生成时间以及市场状态日，方便审计与追溯。
- Redis 连接异常时必须自动降级为直连 Agent，避免影响主流程。

## 交付物
- 技术分析缓存的代码实现与单元测试。
- 可重复执行的 TTL 计算辅助函数。
- 配套的开发文档更新（README）。
